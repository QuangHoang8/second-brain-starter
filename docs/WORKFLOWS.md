# Operating workflows

## Daily (5–10 minutes)

1. Capture useful ideas into `00-Inbox/`.
2. Add a source URL or context while it is fresh. For an article or web page, run `/capture-link` with the URL to fetch, summarize, and predict a domain/tags automatically.
3. Do not interrupt focused work to perfectly classify notes.

## Inbox processing (2–3 times per week)

1. Run `/process-inbox`.
2. Review duplicate detection and proposed destinations.
3. Approve or edit the proposal.
4. Keep raw captures until the canonical note is verified.
5. Commit the result.

## Learning session

1. Pick one measurable objective.
2. Run `/learning-session`.
3. Explain concepts from memory.
4. Complete a practical exercise.
5. Save the session record after review.
6. Update durable knowledge only when you have a reusable insight.

## Troubleshooting

1. Capture symptoms and context.
2. Separate confirmed evidence from hypotheses.
3. Record root cause only when supported by evidence.
4. Record exact verification steps.
5. Create an Experience note after the issue is resolved or sufficiently understood.

## Research a repository

1. Run `/research-repository` with the repository URL.
2. Ask for evidence for important architecture or maintenance claims.
3. Review the resource note.
4. Add a project link only if you have a concrete use case.

## Weekly review (15–30 minutes)

1. Run `/weekly-review`.
2. Review active projects, recent learning, experiences, and Inbox.
3. Choose at most three priorities.
4. Commit the approved review.

## Promotion rule

Inbox is raw material. Knowledge is curated. Experience is first-hand learning. Resource is an external reference. Do not treat these as interchangeable.
