# Metadata and naming conventions

## File names

- Use descriptive names in English technical vocabulary: `AWS-VPC.md`, `Nx-Project-Graph.md`.
- Avoid dates in evergreen knowledge filenames.
- Use dates for sessions, reviews, incidents, and captures.
- One note should represent one main concept or experience.

## IDs

- Lowercase kebab-case.
- Knowledge: `aws-vpc`
- Experience: `exp-20261030-nx-project-graph-ci`
- Learning session: `session-20261030-aws-vpc`

## Status suggestions

- Knowledge: `draft`, `reviewed`, `needs-verification`, `deprecated`
- Experience: `investigating`, `resolved`, `mitigated`, `accepted`, `closed`
- Resource: `to-review`, `reviewed`, `reference`, `deprecated`
- Project: `idea`, `active`, `paused`, `completed`, `archived`

## Quality bar

A note is worth keeping when it helps answer at least one:
- What should I understand?
- How does it work?
- When should I use it?
- What did I try and what happened?
- What would I do differently next time?
- Where can I verify this later?
